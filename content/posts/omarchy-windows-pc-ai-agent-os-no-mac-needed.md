강의나 모임에서 Claude Code 같은 AI 코딩 에이전트를 소개하면 거의 매번 같은 질문이 나온다. "그거 맥에서만 되는 거죠?" 혹은 "AI 제대로 쓰려면 맥북 사야 하나요?"

질문하는 사람 대부분은 윈도우 노트북을 들고 있다. 회사 PC도 윈도우고 집 PC도 윈도우다. 그런데 유튜브와 블로그에서 AI 도구를 시연하는 화면은 대부분 맥이다. 터미널 창이 뜨고, 명령어 몇 줄로 에이전트가 코드를 고친다. 그 장면을 보고 나면 "맥이 있어야 저렇게 되는구나" 하는 인상이 남는다.

결론부터 쓰면, 맥은 필요 없다. 필요한 것은 **에이전트가 일하기 좋은 환경**이고, 그 환경은 지금 윈도우 PC 안에 앱 하나로 띄울 수 있다. 여기서는 그 환경으로 Omarchy를 쓰는 이유와 설치 과정, 그리고 직접 부딪힌 함정을 정리한다.

## 바이브코딩 하려면 맥북 사야 하나 — 반만 맞는 말

맥이 AI 개발에 유리하다는 말에는 근거가 있다. 다만 그 근거를 뜯어보면 "맥이라서"가 아니라 "유닉스 계열 터미널이 기본이라서"인 부분이 크다.

| 흔히 드는 이유 | 실제로 필요한 것 | 윈도우 PC에서 |
|---|---|---|
| 터미널이 편하다 | Bash·Zsh 같은 유닉스 셸 | 리눅스 환경을 띄우면 해결 |
| 개발 도구가 잘 깔린다 | 패키지 관리자 | 리눅스 패키지 관리자가 더 풍부 |
| 에이전트 시연이 다 맥이다 | 같은 화면·같은 명령어 | 같은 리눅스면 명령어가 같다 |
| 로컬 LLM이 잘 돈다 | 큰 통합 메모리 | 이건 실제로 맥(애플 실리콘)의 강점 |

마지막 줄, 로컬에서 큰 언어 모델을 직접 돌리는 경우는 애플 실리콘의 통합 메모리가 확실히 유리하다. 하지만 Claude Code처럼 클라우드 모델을 부르는 코딩 에이전트는 이야기가 다르다. 무거운 계산은 서버에서 하고, 내 컴퓨터는 파일을 읽고 명령어를 실행하는 역할만 한다.

### 클로드 코드 맥북 사양? 공식 요구사항은 RAM 4GB

"클로드 코드 맥북 사양"을 검색해 보는 사람이 많다. 공식 문서의 시스템 요구사항은 생각보다 낮다.

| 항목 | Claude Code 공식 요구사항 |
|---|---|
| OS | macOS 13+, Windows 10(1809)+, Ubuntu 20.04+, Debian 10+ |
| 메모리 | RAM 4GB 이상 |
| CPU | x64 또는 ARM64 |
| 셸 | Bash, Zsh, PowerShell, CMD |
| 네트워크 | 인터넷 연결 필수 |

맥 전용이 아니고, 고사양 맥북 에어나 프로가 필요한 것도 아니다. 무거운 계산은 Anthropic 서버에서 한다. 바이브코딩용 맥북을 고르기 전에 지금 쓰는 윈도우 PC로 먼저 해 보는 게 순서다.

```bash
# macOS, Linux, WSL 공통 설치 명령 (공식 문서 기준)
curl -fsSL https://claude.ai/install.sh | bash
```

```powershell
# Windows PowerShell 설치 명령
irm https://claude.ai/install.ps1 | iex
```

윈도우에서도 PowerShell로 바로 설치된다. 그런데 공식 문서를 더 읽어 보면 단서가 붙는다. 네이티브 윈도우에서는 Git for Windows(Git Bash)를 깔아야 에이전트가 Bash 도구를 쓸 수 있고, 없으면 PowerShell로 명령을 실행한다. 프로젝트가 Bash 스크립트나 유닉스 도구에 기대고 있으면 WSL이나 리눅스 쪽이 낫다는 설명도 있다.

결국 질문은 "맥이냐 윈도우냐"가 아니라 **"에이전트가 유닉스 셸에서 일하게 해 줄 거냐"**로 바뀐다.

## Codex 윈도우 설치가 안 될 때 — 샌드박스와 한글 사용자 폴더

OpenAI Codex도 사정이 비슷하다. 2026년 3월부터 Codex 앱이 윈도우에 나왔고, CLI도 PowerShell 한 줄로 설치된다.

```powershell
# Codex CLI 윈도우 설치 (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"

# Node.js 22 이상이 있으면 npm으로도 된다
npm install -g @openai/codex
```

설치 자체보다 막히는 곳은 **샌드박스**다. 윈도우에는 macOS의 Seatbelt나 리눅스의 bubblewrap 같은 격리 도구가 기본으로 없어서, OpenAI가 윈도우 전용 샌드박스를 따로 만들었다. 모드가 두 개다.

| 모드 | 방식 | 막히는 경우 |
|---|---|---|
| elevated (권장) | 전용 저권한 사용자·방화벽 규칙·권한 경계 | 첫 실행에 관리자 승인 필요. 회사 PC 정책에 막히기 쉬움 |
| unelevated (대안) | 현재 사용자에서 만든 제한 토큰·ACL | 격리가 약함 |
| WSL2 | 리눅스 샌드박스 그대로 | WSL 설치와 리눅스 환경 준비 필요 |

`config.toml`에서 모드를 바꿀 수 있다.

```toml
[windows]
sandbox = "elevated" # 막히면 "unelevated"
```

한국 사용자가 특히 부딪히기 쉬운 문제도 있다. OpenAI 커뮤니티에는 **윈도우 사용자 폴더 이름에 영어가 아닌 글자가 있으면** Codex 앱이 첫 실행 때 로컬 저장소를 못 만들거나 경로 오류를 낸다는 사례가 올라와 있다. 우회법으로 `CODEX_HOME` 환경 변수를 영문 경로로 바꾸거나 영문 이름 계정을 새로 만들라는 답이 달렸다. 윈도우 계정 이름을 한글로 만든 사람이 꽤 많다는 걸 생각하면 가볍게 넘길 문제가 아니다.

OpenAI 문서도 리눅스 도구가 필요하거나 네이티브 샌드박스가 맞지 않으면 WSL2를 쓰라고 안내한다. 결국 Claude Code든 Codex든 **리눅스 환경 하나를 띄워 두면** 이런 윈도우 특유의 함정을 한 번에 피한다.

## 왜 Ubuntu가 아니라 Omarchy인가

윈도우에서 리눅스 환경을 만드는 가장 흔한 방법은 WSL에 Ubuntu를 까는 것이다. 지금까지 강의에서도 그렇게 안내했다. 그런데 Ubuntu WSL은 기본적으로 터미널 창 하나로 시작하고, 리눅스 데스크톱 화면을 주지는 않는다(WSL2에서 GUI 앱 하나하나는 띄울 수 있다). 처음 쓰는 사람은 검은 창 앞에서 "여기가 어디지?" 하고 멈춘다.

Omarchy는 Rails를 만든 DHH가 만든 리눅스 배포판이다. Arch Linux 위에 Hyprland(타일링 창 관리자)를 얹고, 개발 도구와 테마, 단축키를 전부 미리 맞춰 둔 상태로 나온다. 2026년 8월 14일에 나온 4.0 "Quattro"부터는 상단 바·런처·메뉴가 Quickshell 하나로 다시 짜였고, 설치 ISO는 6GB 아래로 줄었다.

AI 에이전트 관점에서 눈에 띄는 점은 따로 있다.

- **기본 에이전트 설정:** 메뉴에서 Claude, Codex, Gemini 등 쓸 에이전트를 고르면 그 자리에서 설치된다.
- **앱이 죽으면 AI가 진단:** 기본 에이전트를 정해 두면 앱이 비정상 종료될 때 알림이 오고, 누르면 에이전트가 원인을 본다.
- **에이전트용 스킬 내장:** 에이전트가 Omarchy 구조를 알고 있어서 "상단 바에 시계 플러그인 만들어 줘" 같은 요청이 통한다.
- **에이전트 사용량 패널:** 상단 바에서 모델별 사용량과 남은 한도를 본다.

DHH는 Quattro 소개 영상에서 Omarchy를 "에이전트와 함께 쓰는 OS"라고 부른다. 그래서 카페와 강의에서는 "리눅스"보다 **AI 에이전트 OS**라는 이름으로 소개하고 있다. 바탕이 리눅스라는 건 한 줄이면 충분하다.

## 윈도우에서 띄우는 방법: Try Omarchy

Omarchy를 진짜로 쓰려면 PC에 직접 설치해야 한다. 4.0부터 윈도우와 듀얼 부트도 된다. 하지만 처음부터 디스크를 나누라고 하면 대부분 거기서 그만둔다.

그래서 권하는 방법은 **Try Omarchy for Windows**다. 윈도우 앱 하나가 가상 머신(VM)을 만들고 그 안에 Omarchy 화면을 띄운다. 디스크를 나누지 않고, 윈도우를 떠나지도 않는다.

| 항목 | 내용 |
|---|---|
| 지원 OS | Windows 10·11, 64비트(x86_64) |
| 필요 조건 | 하드웨어 가상화 켜짐 |
| 받는 용량 | 처음 설정 때 약 2GB |
| 저장 위치 | 기본 `%LOCALAPPDATA%\TryOmarchy` |
| 안 되는 것 | ARM 윈도우 PC, GPU 직접 연결 |
| 맥 | 애플 실리콘 맥용 앱 따로 있음 — macOS 15 이상, 여유 공간 8GB 이상(인텔 맥 미지원) |

설치 순서는 이렇다.

1. 공식 저장소 릴리스에서 `TryOmarchy.exe`를 받아 실행
2. Omarchy를 저장할 폴더 선택
3. "Windows 하이퍼바이저 플랫폼"을 켜라고 하면 허용하고 재시작
4. 계정 선택 — 내 사용자 이름·비밀번호를 정하거나, 빠른 시작(사용자 `omarchy`)
5. 약 2GB를 받은 뒤 Omarchy 화면이 뜬다

내부는 QEMU를 윈도우 하이퍼바이저 플랫폼 위에서 돌리는 구조다. VirtualBox를 따로 깔고 설정할 필요가 없다는 점이 초보자에게 크다.

윈도우 런처 화면은 윈도우의 표시 언어를 따른다. 언어 선택 버튼이 따로 없다. 한국어 윈도우면 한국어로 나와야 하는데, 처음 써 봤을 때는 상당 부분이 영어였다. 그래서 런처의 남은 문구를 한국어로 옮겨 업스트림에 PR로 보냈다. 비슷한 일을 겪는 사람이 있으면 윈도우 표시 언어부터 확인하면 된다.

## 첫 번째 함정: 한글이 안 쳐진다

Omarchy를 띄우고 터미널에서 Claude Code를 실행했다. 한국어로 지시를 쓰려는데 한글이 입력되지 않았다. 처음에는 "한글 입력 아직 안 됨"이라고 결론 내리고 가이드에도 그렇게 썼다. 틀린 결론이었다.

원인은 단순했다. Omarchy 기본 이미지에 **한글 입력기가 들어 있지 않을 뿐**이다. 입력기 프레임워크(fcitx5)는 있고, 한글 엔진만 없다.

```bash
# 한글 엔진과 설정 도구를 함께 설치 (설정 도구는 기본 이미지에 없다)
sudo pacman -S --needed fcitx5-hangul fcitx5-configtool
```

설치한 다음 VM을 한 번 다시 시작하고, fcitx5 설정 도구에서 입력 방법 목록에 Hangul을 추가하고 전환 키를 정하면 된다.

```bash
# fcitx5 설정 도구 열기 → 입력 방법에 Hangul 추가
fcitx5-configtool
```

그러면 한영 전환이 된다. 영어권에서 만든 배포판이라 기본값에 한국어가 없는 것이지, 막혀 있는 건 아니다.

이 경험 때문에 "AI 에이전트 OS로 Claude Code 하기" 가이드는 순서를 이렇게 잡았다.

1. Try Omarchy 설치
2. **한글 입력기 설치** (에이전트에게 한국어로 말하려면 필수)
3. Claude Code 설치와 로그인
4. 첫 프로젝트

## 두 번째 함정: 맥 공유 폴더의 한글 파일 이름

맥용 Try Omarchy에서 공유 폴더로 파일을 넘기면 한글 파일 이름이 이상하게 보일 때가 있다. "보고서.txt"가 자모가 풀어진 모양으로 나온다.

원인은 유니코드 정규화 방식 차이다. macOS는 파일 이름을 NFD(자모를 나눠 저장)로 넘기는 경우가 있고, 리눅스는 NFC(완성형)를 기대한다. 공유 폴더(9p)가 이름을 그대로 넘기면서 생기는 문제다.

```bash
# convmv 는 기본 이미지에 없어 먼저 설치
sudo pacman -S convmv

# ~/shared 는 예시 — 실제 공유 폴더 경로로 바꾼다
# 1) --notest 없이 미리보기만
convmv -f utf-8 -t utf-8 --nfc -r ~/shared
# 2) 백업 후, 미리보기 결과가 맞을 때만 실제 변경
convmv -f utf-8 -t utf-8 --nfc -r --notest ~/shared
```

맥용 앱은 고른 폴더와 같은 이름으로 공유 폴더를 연결하니, 경로부터 확인한다.

공유 폴더 이름을 영문으로 바꾸라는 우회법도 돌아다니지만, 한국어 사용자에게 "파일 이름을 영어로 쓰라"는 건 해결이 아니다. 지금은 변환으로 넘기고, 근본 수정은 업스트림에 제안할 생각이다.

## "고장 나면 어떡해요?" — VM이 샌드박스가 되는 이유

강의에서 Claude Code를 보여주면 두 번째로 많이 나오는 질문이 이거다. "AI가 제 컴퓨터를 망가뜨리면 어떡해요?"

틀린 걱정이 아니다. 코딩 에이전트는 파일을 지우고, 패키지를 설치하고, 설정을 바꾼다. DHH도 영상에서 권한 확인을 건너뛰는 모드로 Claude Code와 Codex를 띄우는 단축 명령을 보여준다. 매번 "이 명령 실행해도 돼요?"라고 묻지 않으니 빠르지만, 실수하면 그대로 실행된다.

이 걱정에 대한 답이 VM이다.

| 상황 | 내 윈도우에 직접 | Try Omarchy VM 안에서 |
|---|---|---|
| 에이전트가 설정을 망침 | 윈도우가 이상해질 수 있음 | VM 안만 영향(공유 폴더 제외) |
| 패키지를 잘못 깔았음 | 직접 정리해야 함 | VM 안에서 정리하거나 다시 만들기 |
| 아예 엉망이 됨 | 재설치 부담 | VM을 지우고 다시 만들면 끝 |
| 권한 확인 생략 모드 | 권하기 어려움 | 위험 범위가 VM과 공유 폴더로 좁아짐 |

PC에 직접 설치한 Omarchy에는 안전장치가 하나 더 있다. 업데이트할 때마다 직전 상태를 스냅샷으로 남기고, 부팅할 때 이전 스냅샷을 골라 되돌릴 수 있다. 다만 이건 그 기능이 구성된 설치 환경 이야기다. 맥용 Try Omarchy처럼 디스크 구성이 다른 VM에서는 같은 복구 목록이 없을 수 있다. VM에서는 "지우고 다시 만들기"를 기본 복구 수단으로 생각하는 편이 맞다.

한 가지 예외는 **공유 폴더**다. 내 컴퓨터 폴더를 VM과 공유해 두면, 에이전트가 그 폴더의 파일은 고치고 지울 수 있다. 연습할 때는 공유를 끄거나 연습용 빈 폴더만 연결해 두는 게 안전하다.

그래서 가이드에는 기존 설치 방법은 그대로 두고, **"영상 따라 하기·연습은 Omarchy VM에서"**라는 경로를 하나 더 넣었다. 익숙해진 뒤에 내 컴퓨터에서 쓰든, 듀얼 부트로 옮기든 그건 그다음 문제다.

중요한 파일은 VM 밖에 백업해 두라는 건 Try Omarchy 공식 안내에도 있다. 샌드박스는 내 PC를 지켜 주지만, VM 안의 작업물까지 지켜 주지는 않는다.

## 윈도우와 맥 사용자가 같은 화면을 본다

맥 사용자에게는 "그냥 맥 터미널에서 하면 되지 않냐"는 반론이 있을 수 있다. 맞는 말이다. 맥 터미널에서도 Claude Code는 잘 돈다.

그래도 강의와 커뮤니티에서는 맥 사용자에게도 Omarchy VM을 권하고 있다. 이유는 하나다. **모두가 같은 환경을 보게 하려고.**

- 윈도우 사용자와 맥 사용자가 같은 단축키(Super+Space 메뉴, Super+Enter 터미널)를 쓴다. 맥에서 `Command+Space`를 누르면 Spotlight가 먼저 열릴 수 있는데, 시스템 설정의 손쉬운 사용에서 Try Omarchy에 권한을 주면 VM으로 전달된다
- 같은 명령어가 같은 결과를 낸다. "맥은 이렇고 윈도우는 저래요"가 사라진다
- 질문 게시판에 올라오는 스크린샷이 다 같은 화면이라 답하기 쉽다
- 리눅스에 익숙해지면 서버, 클라우드, 컨테이너 작업으로 넘어가기도 쉽다

AI 에이전트가 일하는 곳은 결국 리눅스인 경우가 많다. 클라우드 서버도 리눅스고, 에이전트가 띄우는 컨테이너도 리눅스다. 사람이 그 환경에 익숙해져 있으면 에이전트가 하는 일을 따라가기도 쉽다.

---

## 실전: Try Omarchy에서 Claude Code까지

설치를 마친 VM에서 실제로 하는 순서를 정리한다.

```bash
# 1. 터미널 열기: Super + Enter

# 2. 한글 입력기와 설정 도구 설치 (위 함정 참고)
sudo pacman -S --needed fcitx5-hangul fcitx5-configtool

# 3. Claude Code 설치 (리눅스 설치 명령)
curl -fsSL https://claude.ai/install.sh | bash

# 4. 연습용 폴더를 만들고 실행
mkdir -p ~/practice && cd ~/practice
claude
```

처음 실행하면 로그인 안내가 나온다. VM 안의 브라우저로 로그인하면 된다. 이때 계정은 Claude Code를 쓸 수 있는 유료 구독이나 API 결제 계정이어야 한다. 무료 Claude 계정만으로는 쓸 수 없다. 로그인한 뒤에는 한국어로 하고 싶은 일을 말하면 된다.

Omarchy 메뉴에서 기본 에이전트를 지정해 두면 `Ctrl + Super + Shift + A`로 바로 불러 쓸 수도 있다. 위 설치 스크립트로 깐 Claude Code는 알아서 최신 버전을 유지하고, 직접 올리고 싶으면 `claude update` 한 줄이면 된다. Omarchy에서 `mup`은 mise로 관리하는 도구들을 한꺼번에 업데이트하는 명령이다. 에이전트를 Omarchy 메뉴로 설치했다면 이쪽으로 함께 올라간다.

텔레그램으로 Claude Code를 원격 조작하는 방법은 [Claude Code 채널 텔레그램 설정](/posts/claude-code-channels-telegram-setup/) 글에 정리해 두었다. VM 안의 Claude Code에도 같은 방식이 통한다.

## 자주 묻는 질문

### 클로드 코드는 윈도우에서 되나요?

된다. PowerShell 설치 명령(`irm https://claude.ai/install.ps1 | iex`)으로 바로 설치된다. 다만 Bash 도구를 쓰려면 Git for Windows가 필요하고, 유닉스 도구에 기대는 프로젝트라면 WSL이나 리눅스 환경이 편하다.

### 클로드 코드 윈도우 터미널은 뭘 쓰면 되나요?

네이티브 윈도우라면 Windows Terminal에 PowerShell이나 Git Bash 조합이 무난하다. 터미널을 고르는 것부터 부담이라면 Omarchy VM을 띄우는 쪽이 빠르다. 터미널, 셸, 패키지 관리자가 이미 맞춰져 있다.

### Codex를 윈도우에 설치했는데 실행이 안 돼요.

샌드박스 설정(관리자 승인)과 사용자 폴더 경로를 먼저 의심한다. 사용자 폴더 이름에 한글이 있다면 위의 `CODEX_HOME` 우회법을 본다. 그래도 안 되면 WSL2나 리눅스 VM에서 실행한다.

### 맥북 에어로 충분한가요? 꼭 프로여야 하나요?

클라우드 모델을 쓰는 코딩 에이전트라면 에어로도 충분하고, 윈도우 PC로도 충분하다. 맥이 확실히 유리한 건 큰 로컬 모델을 직접 돌릴 때다.

### AI가 컴퓨터를 망가뜨리면 어떡하나요?

VM 안에서 쓰면 영향이 대부분 VM에서 끝난다. 단, 공유 폴더를 연결했다면 그 폴더의 파일은 바뀔 수 있으니 연습 중엔 공유를 꺼 둔다. 망가지면 VM을 지우고 다시 만든다.

## 정리

AI 코딩 에이전트를 쓰려고 맥을 살 필요는 없다. 에이전트에게 필요한 건 유닉스 셸과 잘 갖춰진 도구이고, 사람에게 필요한 건 망가져도 괜찮은 연습장이다.

윈도우 PC에서 Try Omarchy를 띄우면 둘 다 생긴다. 앱 하나로 AI 에이전트 OS가 뜨고, 한글 입력기 하나만 더 깔면 Claude Code에 한국어로 일을 시킬 수 있다. 공유 폴더만 조심하면, 무엇이 고장 나도 VM 안의 일이다.

Omarchy 설치와 사용법은 한국어 커뮤니티 카페 [오마키(Omarchy) 한국 사용자 모임](https://cafe.naver.com/omarchykr)에 단계별로 정리하고 있다. DHH의 81분짜리 Quattro 소개 영상도 주제별 한국어 해설로 나눠 올려 두었다.
